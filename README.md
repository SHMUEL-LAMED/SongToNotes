# כלי מוזיקה (SongToNotes)

אוסף כלי מוזיקה שרצים במלואם בדפדפן. שום קובץ שמע לא נשלח לשרת, אין מפתחות
API ואין צורך בהתקנה.

הכניסה חופשית. מי שמתחבר עם Google מקבל פרופיל והיסטוריה אישית ב־Supabase,
שבה נשמרים התווים, נתוני הניתוח וההגדרות — אבל קובץ האודיו עצמו תמיד נשאר
במכשיר.

## הכלים

| כלי | מה הוא עושה |
| --- | --- |
| **שיר לתווים** | זיהוי תווים פוליפוני, קצב וסולם; ייצוא MusicXML, MIDI, ABC, CSV, SVG והדפסה |
| **יצירת צלצול** | חיתוך קטע מגל הקול, כניסה ויציאה רכות, נרמול עוצמה וייצוא WAV |
| **הסרת שירה** | הפרדת אמצע/צדדים לגרסה אינסטרומנטלית או לווקאל בלבד, עם שמירה על הבס |
| **מאט ומאיץ** | האטה או האצה בלי לשנות גובה, והזזת גובה בלי לשנות קצב — עם לולאת תרגול |
| **מטרונום** | תזמון מבוסס שעון האודיו, הדגשות, חלוקות משנה, טאפ־טמפו ושלושה צלילים |
| **מכוון כלים** | מכוון כרומטי מהמיקרופון עם מחוג סנטים, כיול A4 ומסננים לגיטרה, בס, כינור ויוקללה |
| **פסנתר וירטואלי** | שלוש אוקטבות בעכבר, במגע או במקלדת, פדל סוסטיין, הדגשת סולמות והקלטה ל־MIDI |
| **מאמן שמיעה** | תרגול מרווחים, סוגי אקורדים ודרגות בסולם בשלוש רמות, עם ניקוד ורצף הצלחות לכל תרגיל |
| **מזהה קצב וסולם** | BPM, סולם, קוד Camelot ופרופיל צלילים — בשניות, בלי להריץ את מודל התווים |
| **תמלול לטקסט** | דיבור לטקסט עם חותמות זמן (זיהוי בשרת, בלי להתקין דבר; עברית ועוד שפות, גם הקלטות של שעות); עריכה במקום וייצוא TXT, SRT ו־VTT |
| **מזהה אקורדים לגיטרה** | אקורדים לאורך השיר עם דיאגרמות אחיזה, טרנספוזיציה וקאפו, דף אקורדים ושליחה לשירון |
| **שירון** | מילים עם אקורדים מעליהן, טרנספוזיציה, גלילה אוטומטית להופעה, הדפסה ושמירה |
| **המרת פורמטים** | כל קובץ שמע ל־MP3 (מקודד LAME בדפדפן) או WAV, עם קצב דגימה, ערוצים, איכות, חיתוך ועוצמה |
| **וידאו לאודיו** | פס הקול של סרטון כקובץ, או ישר לכל כלי אחר באתר |
| **מאמן קצב** | תבניות קצב בשלוש רמות; כל הקשה נמדדת מול שעון האודיו, עם ציון ונטייה להקדים או לאחר |
| **מיקסר ולופר** | עד שמונה ערוצים עם עוצמה, פאן, השתקה וסולו, לולאה, ומיקס אחד ל־WAV |
| **מילים מסונכרנות** | מילות השיר עם זמן לכל מילה (בשרת), קריוקי שנדלק מילה אחר מילה, ייצוא LRC ו־SRT |
| **טקסט לדיבור** | הקראה בקולות של המכשיר, וקובץ MP3 מהשרת |
| **מזהה שיר** | כמה שניות מהמיקרופון או מקובץ, ובחזרה שם, אמן וקישורים להאזנה (דורש מפתח AudD) |
| **העוזר** | בוט שעונה על שאלות — ומבצע באתר את מה שמבקשים ממנו: כותב שיר לשירון, מפעיל מטרונום, מנגן, מתמלל, מפריד, שומר |

כל כלי יושב על כתובת משלו (`#/metronome`, `#/tuner` וכן הלאה), כך שאפשר לשמור
אותו כסימנייה ושכפתור החזרה של הדפדפן יעבוד.

כל כלי שומר את מה שעשית באזור האישי — תווים, צלצולים, קריוקי, תמלולים, הקלטות
פסנתר, ניתוחים, אימוני שמיעה, אקורדים, שירים, המרות, מיקסים, מילים והקראות —
וקבצי התוצאה עולים לענן וזמינים מכל מכשיר. לכל עבודה מסונכרנת אפשר ליצור קישור
ציבורי (`#/s/<token>`) שכל אחד פותח, בלי התחברות. הפרופיל משותף עם [אתר הצלצולים](https://shmuel-lamed.github.io/Ringtones/)
— אותה התחברות ואותה היסטוריה.

## הפעלה מקומית

```bash
npm install
npm run dev
```

מודל הפרדת השירה (כ־180MB) אינו שמור ב־git: `npm run build` מוריד אותו
לתיקייה `models/` בפעם הראשונה ומעתיק אותו אל `dist/model/`, כך שהאתר
מגיש אותו בעצמו. שרת הפיתוח עובד גם בלעדיו — עד שמריצים `npm run fetch-model`
הוא נופל לכתובת המקורית של המודל.

הטבלאות ומדיניות ההרשאות של הפרופיל — `profiles`, `transcriptions`,
`ringtones`, `works` ו־`stt_usage` — מוגדרות ב־`supabase/schema.sql`, שאותו
יש להריץ בפרויקט ה־Supabase.

התמלול לטקסט רץ בפונקציית Edge, `supabase/functions/transcribe`, כדי שהגולש
לא יצטרך להוריד מודל למכשיר. הפונקציה מקבלת חלון של ההקלטה (WAV מונו
16 kHz), מעבירה אותו לשירות זיהוי דיבור בממשק תואם OpenAI ומחזירה משפטים
עם זמנים. המפתח לשירות נשמר רק בשרת — כסוד של הפונקציה או כשורה בטבלה `private.stt_settings` שרק הפונקציה קוראת — ולעולם לא באתר:

| סוד | משמעות |
| --- | --- |
| `STT_API_KEY` | המפתח לשירות — חובה |
| `STT_BASE_URL` | כתובת הבסיס; ברירת מחדל `https://api.openai.com/v1` (Groq: `https://api.groq.com/openai/v1`) |
| `STT_MODEL` | ברירת מחדל `whisper-1` (Groq: `whisper-large-v3`) |
| `STT_DAILY_SECONDS` | מכסת אודיו יומית לחשבון, ברירת מחדל ארבע שעות |

רק גולש מחובר יכול לתמלל, והמכסה היומית נרשמת ב־`stt_usage` כדי שאדם אחד
לא ינצל את המפתח של כולם.

באותו מנגנון עובדות עוד שתי פונקציות:

- `supabase/functions/ai` — מודל השפה: פיסוק וחלוקה לפסקאות של תמלול,
  סיכום, תרגום, זיהוי דוברים, והעוזר שבפינת כל עמוד. הפונקציה יודעת לדבר
  עם תריסר ספקים (ראו „הספקים של העוזר” למטה); מספיק להזין מפתח אחד.
  הגדרות נוספות: `AI_DAILY_TOKENS` (ברירת מחדל 300,000 טוקנים לחשבון ליום).
- `supabase/functions/separate` — הפרדת שירה בשרת דרך Replicate, כך שהדפדפן
  לא מוריד את הרשת של 180MB. השיר עולה לתיקייה הפרטית של הגולש, המודל מקבל
  כתובת חתומה, והערוצים חוזרים דרך הפונקציה. הגדרות: `SEPARATION_API_KEY`
  (טוקן של Replicate), `SEPARATION_MODEL` (ברירת מחדל `ryan5453/demucs`),
  `SEPARATION_INPUT`, `SEPARATION_STEMS_INPUT` (הקלט למצב הערוצים; ברירת המחדל מתאימה ל־Demucs), `SEPARATION_DAILY`. עד שיש טוקן, הכלי מציע להפריד
  בדפדפן כמו קודם.

המכסות היומיות של שתיהן נרשמות ב־`ai_usage`.

### אזור הניהול

לחשבון של בעל האתר — הכתובת שמוגדרת בסוד `ADMIN_EMAILS` של הפונקציה — יש
כניסה נוספת מהאזור האישי: `#/admin`, דף אחד שמרכז את כל האתר. סקירה עם
המספרים הגדולים והגרפים (מה נשמר, מי נרשם, כמה טוקנים ודקות תמלול נשרפו,
מתי בשבוע עובדים באתר), רשימת החשבונות עם מה שכל אחד שמר וכמה מקום הוא
תופס, כל הפריטים השמורים, הקישורים הציבוריים והצפיות בהם, המפתחות של השרת
ויומן של כל פעולה שבוצעה מהאזור.

השער יושב בשרת, לא בדפדפן: `supabase/functions/admin` בודקת את הכתובת
המאומתת שבטוקן של הפונקה לפני שהיא עונה, ורק אז ניגשת לנתונים עם
service role. מדיניות ההרשאות שבסכימה נשארת בתוקף לכל השאר — גם למנהל —
וכל חשבון אחר שיגיע לכתובת הזאת יקבל 403. הכפתור באזור האישי הוא רק דלת:
הסתרה אינה הרשאה.

הפעולות שאפשר לבצע משם: מחיקת פריט (כולל הקובץ שלו בענן), ביטול קישור
ציבורי, איפוס המכסה היומית של חשבון, חסימת חשבון או מחיקתו, והזנה או מחיקה
של הגדרת שרת בטבלה `private.stt_settings`. מפתח שמוגדר כסוד של הפונקציה
גובר על הטבלה ואי אפשר לשנות אותו משם, והערכים עצמם לעולם אינם חוזרים
לדפדפן — רק ארבע הספרות האחרונות. כל פעולה נרשמת ב־`admin_audit`, שאין
אליה מדיניות קריאה מלבד ה־service role.

### הספקים של העוזר

שיחה עם מודל שפה היא מצרך זול, וכמה שירותים נותנים אותה בחינם. פונקציית
`ai` מכירה את הרשימה הזאת ומשתמשת בכל ספק שיש לו מפתח, לפי הסדר; ברגע
שספק עמוס, מיצה את המכסה, נשבר או כבר לא מגיש את המודל שביקשנו — הבקשה
עוברת לספק הבא, ורק אם כולם נפלו יחד היא ממתינה רגע ומנסה שוב. אין מה
להגדיר מעבר להזנת מפתח אחד:

| ספק | המפתח | חינם | הערה |
| --- | --- | --- | --- |
| Groq | `GROQ_API_KEY` | ✓ | מהיר מאוד; אותו חשבון כמו התמלול |
| Cerebras | `CEREBRAS_API_KEY` | ✓ | המהיר ביותר כרגע |
| Google Gemini | `GEMINI_API_KEY` | ✓ | מכסה יומית נדיבה, עברית טובה |
| GitHub Models | `GITHUB_TOKEN` | ✓ | מפתח אישי רגיל של GitHub |
| OpenRouter | `OPENROUTER_API_KEY` | ✓ | דגמי `:free` בלבד כברירת מחדל |
| Mistral | `MISTRAL_API_KEY` | ✓ | דרגת ניסוי חינמית |
| SambaNova | `SAMBANOVA_API_KEY` | ✓ | |
| NVIDIA NIM | `NVIDIA_API_KEY` | ✓ | |
| Hugging Face | `HF_TOKEN` | ✓ | |
| Together | `TOGETHER_API_KEY` | ✓ | דגמי `-Free` |
| DeepSeek | `DEEPSEEK_API_KEY` | | בתשלום |
| OpenAI | `OPENAI_API_KEY` | | בתשלום |

`AI_PROVIDERS` קובע את הסדר כשרוצים סדר אחר — למשל `AI_PROVIDERS=cerebras,gemini,groq`.
שירות שאינו ברשימה עובד דרך `AI_API_KEY` + `AI_BASE_URL` (+`AI_MODEL`), והוא
נוסה ראשון. המודל שענה נשמר ב־`AI_MODEL` ומשמש נקודת פתיחה לבקשה הבאה, כך
ששם מודל שיצא משימוש מתקן את עצמו.

### מה העוזר יכול לעשות

העוזר אינו רק עונה: הוא מבצע. `src/lib/assistantActions.ts` מחזיק קטלוג של
כל הפעולות שהאתר מציע — לכל אחת מזהה, פרמטרים מוגדרים, והאם היא קריאת מידע
או שינוי — והוא מה שנשלח למודל בכל בקשה, יחד עם תיאור קצר של מה שעל המסך
ברגע זה. המודל עונה בטקסט ובבלוקים בפורמט:

```
{"action": "metronome.set", "params": {"bpm": 120, "meter": "3/4"}}
```

הדף מפרק אותם (`src/lib/assistantProtocol.ts`), בודק כל קריאה מול הקטלוג,
ומריץ אותה דרך הכלי שרשום לאותה פעולה (`src/lib/useAssistantTool.ts`). כלי
שאינו פתוח נפתח מעצמו וממתינים שיעלה. פעולת קריאה מחזירה את המידע למודל
כהודעה הבאה בשיחה, כך שהוא יכול להסתכל, להסיק ולהמשיך — עד ארבעה סבבים
לבקשה אחת. פעולה הרסנית (מחיקת עבודה, ניקוי הכלי) נעצרת ומחכה לאישור
הגולש, וכל מה שבוצע מופיע כשורות מתחת לתשובה, עם מה שהצליח ומה לא.

מה שהעוזר לא יכול: לבחור קובץ מהמכשיר, להקליט במקום הגולש, או כל דבר
שאינו ברשימה. כשפעולה דורשת קובץ ואין קובץ — הוא מבקש מהגולש לבחור אותו.
במצב „שאלה” הוא עונה בלבד ואינו נוגע בכלום.

## בדיקות

```bash
npm run test     # בדיקות יחידה
npm run check    # lint + בדיקות + בנייה — אותו רצף שרץ ב־CI
```

הבדיקות מכסות את הלוגיקה המוזיקלית הטהורה: זיהוי הסולם ואיות התווים, אמידת
הקצב ונעילת הפעמה, פירוק משכים לערכי תווים שאפשר לכתוב, קידוד ה־WAV, המרות
הגובה והתדר, הייצוא ל־ABC ול־MusicXML, ובניית השאלות של מאמן השמיעה. הן
מכסות גם את העוזר: פירוק בלוקי הפעולה מתוך תשובה (כולל הצורות שמודלים
נוטים לכתוב בהן), בדיקת הפרמטרים מול הקטלוג, והרצת פעולה דרך הכלי שרשום
לה — כולל פתיחת כלי שאינו על המסך. חלקן
בדיקות תכונה — למשל שכל איות חוזר בדיוק לתו שממנו יצא, שכל תיבה מתמלאת
בדיוק, ושכל שאלה במאמן השמיעה באמת משמיעה את המרווח או האקורד שהיא שואלת
עליו.

## בדיקה בדפדפן אמיתי

`npm run test:browser` מריץ את האתר הבנוי בדפדפן אמיתי ובודק מה שהידור נקי
לא בודק: שכל עשרת הכלים נפתחים, שקובץ שמע עובר את כל הצינור, שהעריכה
עובדת מהמקלדת, ושהקובץ שיוצא בהורדה באמת נשמע כמו שביקשו ממנו. יש להריץ
`npm run preview` בחלון אחר לפני כן, ולהתקין את Playwright
(`npm i -g playwright`) — הוא אינו תלות של האתר עצמו.

## איך העיבוד עובד

- **זיהוי תווים** רץ על Spotify Basic Pitch ב־Web Worker, כך שהדף נשאר זמין
  לאורך כל הניתוח. אחריו מגיע צינור ניקוי: איחוד שברי תווים, סילוק הרמוניות,
  חילוץ מנגינה ראשית, זיהוי קצב ונקודת המשקל הראשונה, וזיהוי סולם.
- **הפרדת השירה המלאה** מריצה את רשת Demucs (בפורמט ONNX) בדפדפן, על
  WebGPU כשיש ועל WebAssembly כשאין. קובץ המודל מגיע מהאתר עצמו — הוא נארז
  לתוך `dist/model/` בזמן הבנייה — ולא משרת חיצוני, כך שכל רשת שמאפשרת
  לפתוח את האתר מאפשרת גם את ההפרדה. הוא נמשך ברקע כבר כשנכנסים לכלי
  הצלצולים או להסרת השירה — בחיבור שאינו סלולרי, ובמכשירי מגע רק כשהדפדפן
  מדווח על Wi-Fi — כך שהלחיצה על הכפתור לא מתחילה בהמתנה ארוכה. אחרי הטעינה
  הראשונה הוא נשמר ב־Cache Storage של הדפדפן, ובפעמים הבאות ההכנה מיידית. הממשק עצמו לא מזכיר את
  כל זה: המבקר רואה „מכין את ההפרדה בפעם הראשונה” ופס התקדמות, ותו לא.
- **שאר הכלים** אינם נוגעים במודל. המכוון משתמש בקורלציה עצמית מנורמלת
  (שיטת McLeod), מזהה הקצב בפלוקס ספקטרלי, ומזהה הסולם בבנק מסנני Goertzel
  שמייצר כרומה ומשווה אותה לפרופילי Krumhansl. ההאטה היא חפיפה־וחיבור של
  גרעינים, וההסרה המהירה של השירה היא הפרדת אמצע/צדדים. כולם נמדדים
  באלפיות שנייה, לא בשניות.
- **הייצוא** מקודד WAV בעצמו במקום להישען על MediaRecorder, כדי שהקובץ ייצא
  זהה בכל דפדפן.

## איך הדיוק נבדק

התוצאות נמדדות מול קובצי אודיו סינתטיים שנוצרים יחד עם רשימת התווים האמיתית
שלהם — מנגינה עם כניסה שאינה על הפעמה, רצף תווים חוזרים על אותו גובה, אקורדים,
וריצת שמיניות מהירה בסולם עם דיאז. הבדיקה מריצה את האתר הבנוי בדפדפן אמיתי
ומשווה את הפלט לתווים המקוריים.

בבדיקה האחרונה, מנגינת „Twinkle Twinkle” שהמודל זיהה כ־72 תווים גולמיים יוצאת
מהצינור כ־28 תווים — בדיוק כמו המקור — ונכתבת כ־
`C4 C4 G4 G4 | A4 A4 G8 | F4 F4 E4 E4 | D4 D4 C8`.

## מהירות

רוב זמן הניתוח הוא המודל עצמו — בקובץ של 20 שניות: טעינת מודל 35 מ״ש, הרצת
המודל כ־34 שניות, ועיבוד התווים 120 מ״ש. כלומר המהירות נקבעת כמעט לחלוטין
לפי האם הדפדפן מספק האצת GPU.

הניתוח רץ ב־Web Worker כדי שהדף יישאר זמין. חלק מהדפדפנים — בעיקר ספארי ישן
בנייד — לא נותנים ל־Worker גישה לכרטיס המסך, ואז המודל היה נופל לחישוב על
המעבד בלבד ואיטי פי כמה. במקרה כזה האתר מריץ את הניתוח ישירות בדף, שם הגישה
לכרטיס המסך בדרך כלל כן קיימת. אם גם שם אין האצה, האתר חוזר להרצה ברקע וכותב
בפירוש על מה הניתוח רץ וכמה זמן לקח.

מנוע התווים נטען רק כשנכנסים לכלי שצריך אותו, כך שהדף הראשי ושאר הכלים
נפתחים בלי לשלם עליו. לקיצור זמן הניתוח עצמו: אפשר לסמן קטע בגל הקול ולנתח
רק אותו.

## דיוק בשימוש אמיתי

המנוע עובד בצורה הטובה ביותר על שירה נקייה או כלי נגינה יחיד. בשיר מלא עם
כמה כלים, תופים ושירה יחד ייתכן שיידרש תיקון ידני בתוכנת תווים כמו MuseScore.
קובץ MusicXML מיועד בדיוק להמשך העריכה הזאת.

אם התוצאה עמוסה מדי, כדאי להוריד את הרגישות או להעלות את ניקוי ההרמוניות —
שני הכוונונים משפיעים מיד, בלי ניתוח מחדש.

הסרת השירה עובדת על מיקס סטריאו שבו השירה ממורכזת, וזה נכון ברוב ההקלטות
המסחריות. בהקלטת מונו, או כשהשירה מוזזת לצד, לא נשאר מה להפריד.

## התקנה כאפליקציה ועבודה בלי אינטרנט

האתר הוא אפליקציית ווב מותקנת (PWA): אפשר להוסיף אותו למסך הבית בנייד או
להתקין אותו מהדפדפן במחשב, ואז הוא נפתח בחלון משלו עם קיצורי דרך ישירים
לתווים, לצלצול, לקריוקי ולמטרונום.

מכיוון שכל העיבוד ממילא מתבצע במכשיר, האתר עובד גם בלי חיבור: Service Worker
שומר את המעטפת ואת קובצי הבנייה בהתקנה הראשונה, ומגיש אותם כשאין רשת. רק
ההתחברות ושמירת ההיסטוריה מחכות לחיבור, והאתר אומר זאת בהודעה קטנה. קובץ
ה־WebAssembly הגדול של מנוע התווים לא נשמר במטמון בכוונה, כדי לא למלא את מכסת
האחסון של הדפדפן; מודל הפרדת השירה, לעומת זאת, כן נשמר אחרי הטעינה הראשונה,
כי בלעדיו כל הפעלה הייתה מתחילה מאפס. גרסה חדשה נתפסת מעצמה ומוצעת לרענון
בלחיצה אחת.

## נגישות ועיצוב

- ערכת נושא בהירה וכהה, עם מעקב אחרי העדפת המערכת ומעבר ידני שנשמר.
- כל צבעי הממשק נגזרים משכבת משתני CSS אחת, וכל כלי צובע את אותם רכיבים
  בגוון משלו.
- ניווט מלא במקלדת, טבעות מיקוד גלויות, ו־`prefers-reduced-motion` מכבד.
- כפתור „דלג לתוכן” ראשון בסדר ה־Tab מדלג על סרגל העליון. הוא מזיז את המיקוד
  בעצמו ולא דרך קישור עוגן, כי עוגן היה נכתב אל ה־hash ומפיל את הניווט לדף
  הבית.
- מעבר בין כלים משנה רק את ה־hash, ולכן יש אזור `aria-live` שמכריז על הכלי
  שנפתח — אחרת קורא מסך לא היה יודע שהדף התחלף.
- סימון הקטע בגל הקול נגיש גם בלי עכבר: לכל קצה יש ידית שמגיעים אליה ב־Tab
  ומזיזים בחיצים, והיא מופיעה רק כשהמיקוד עליה כדי לא לשנות את המראה.
- בכל מקום שנוצר בו קובץ יש כפתור שיתוף לצד ההורדה, שמעביר אותו ישירות
  לאפליקציה אחרת במכשירים שתומכים בכך.

## פרטיות

כל עיבוד האודיו מתבצע במכשיר של המשתמש. אין העלאה של השיר לשרת, אין צורך
במפתח API, וגם הקלטת המיקרופון וההשמעה של התוצאה נשארות מקומיות לחלוטין.

## פריסה

פריסה אוטומטית ל־GitHub Pages בכל דחיפה ל־`main`, אחרי שה־lint, הבדיקות
והבנייה עוברים. בכל בקשת משיכה רץ אותו רצף בנפרד (`.github/workflows/ci.yml`),
כך שבנייה שבורה לא מגיעה לאתר החי. מודל הפרדת השירה נשמר במטמון של GitHub
Actions בין ריצות, כך שהוא יורד פעם אחת ולא בכל בנייה.
